> **נספח תפעולי — אינו חוק ממוספר.** הוא מתעד איך גבולות ספר החוקים נאכפים בפועל על קלוד קוד. עדכון ספר החוקים או הוספת חוק 16 — רק בהכרעת נחי.
>
> נכתב 15.08.2026, בעקבות הצפת הנושא על-ידי נחי.

## מה זה מצב אוטומטי

מצב הרשאות (`auto`) שבו **מסווג** — מודל שני — בודק כל קריאה לכלי במקומך: מאשר את מה שהוא מעריך כסיכון נמוך, עוצר ומבקש אישור על מה שמסוכן, וחוסם את מה שאסור.

**שתי עובדות שחייבים להכיר:**

1. **בתוכניות Pro/Max/Team זו ברירת המחדל ההתחלתית** של כל סשן חדש בטרמינל (מגרסה v2.1.228). כלומר — המצב פעיל גם אם לא הגדרת דבר.
2. **כברירת מחדל המסווג מתיר push לכל ענף של הריפו שעובדים בו ופתיחת PR.** בלי הגדרה, זו התנגשות ישירה עם חוק 12.

**איך מזהים ומחליפים:**

| פעולה | איך |
|---|---|
| לזהות שהמצב פעיל | `⏵⏵ auto mode on` בשורת הסטטוס |
| להחליף מצב תוך כדי סשן | `Shift+Tab` (מ-`auto` הלחיצה הראשונה מחזירה ל-Manual) |
| לפתוח סשן במצב ידני | `claude --permission-mode default` |
| לבטל את המצב לגמרי | `"disableAutoMode": "disable"` בכל קובץ הגדרות — מוציא את `auto` ממחזור `Shift+Tab` |

## שלוש השכבות — ולמה חלק מהן לא יכול לחיות בריפו

הגבול המרכזי: **`autoMode` — הבלוק שמכוונן את המסווג — אינו נקרא מ-`.claude/settings.json` של הריפו ולא מ-`.claude/settings.local.json`.** הוא נקרא רק מ-`~/.claude/settings.json`, מ-managed settings, ומדגל `--settings`. הסיבה: שני הקבצים יושבים בתיקיית הריפו, ולכן ריפו שנמשך מהרשת או שלב build היו יכולים להזריק לעצמם כללי היתר.

| שכבה | קובץ | בריפו? | תפקיד |
|---|---|---|---|
| **אכיפה קשיחה** | `.claude/settings.json` | ✅ | `ask`/`deny` — נבדקים **לפני** המסווג. `deny` חוסם בלי שהמסווג מתייעץ; `ask` מכריח שאלה שהמסווג לא יכול לעקוף |
| **הנחיה למסווג** | `CLAUDE.md` בשורש | ✅ | המסווג קורא את אותו `CLAUDE.md` שקלוד טוען — כללי הפרוזה שם מנחים את שניהם |
| **סביבה מהימנה** | `~/.claude/settings.json` | ❌ | `autoMode` — במחשב של נחי בלבד |

מכאן גם: **אי-אפשר לכפות או לכבות את המצב האוטומטי מהריפו** — הערך `"auto"` תחת `permissions.defaultMode` בהגדרות פרויקט אינו נכנס לתוקף.

## מה מוגדר בריפו — `.claude/settings.json`

| כלל | חוק | למה |
|---|---|---|
| `deny` על `.env`, `*.token`, `*.key`, `*.pem`, `secrets.*`, `state.json`, `CLAUDE.local.md` | 2 | סודות לא נקראים ולא נכתבים. כלל `Read` חוסם אוטומטית גם `Edit`/`Write` על אותו נתיב |
| `deny` על `git push --force`, `git push -f`, `git reset --hard` | 13 | כתיבה מחדש של היסטוריה = שבירת משטר הגיבוי |
| `ask` על `git push` | 12 | שער האישור האנושי לפני שמשהו יוצא לגיטהאב |
| `ask` על `rm`, `git rm` | 12 | מחיקה — רק באישור מפורש נוסף |
| `ask` על `00-Constitution/`, `09-Monday-Agents/agents/`, `07-Department-Agents/`, `00-EXTERNAL-AGENTS-LAW.md` | 12, 14 | החוקה וחוקות הסוכנים — טיוטה ואישור לפני שינוי |
| `ask` על `99-Intake/` | README | ארכיון חומרי גלם — קריאה בלבד |
| `ask` על `mcp__monday_com__*` | 13, 5 | קלוד קוד מאמת ריפו בלבד. כל נגיעה במאנדיי מהריפו הזה — עוצרת |

**שתי מלכודות תחביר שכדאי לזכור לפני עריכת הקובץ:**

- בהגדרות פרויקט, נתיב שמתחיל ב-`/` עוגן ל**שורש הריפו** — לא לשורש הדיסק. לנתיב מוחלט אמיתי צריך `//`.
- כללי קבצים נבדקים מול `Edit(...)` ו-`Read(...)` **בלבד**. כלל שנכתב כ-`Write(...)` או `NotebookEdit(...)` מתקבל, מדפיס אזהרה ב-startup — ו**לעולם לא נבדק**.

## מה נחי מגדיר במחשב שלו — `~/.claude/settings.json`

כדי שהקובץ בריפו והמערכת החיה יהיו זהים (חוק 13), זה הנוסח המדויק להדבקה. אם כבר קיים שם תוכן — ממזגים, לא דורסים.

```json
{
  "autoMode": {
    "environment": [
      "$defaults",
      "Organization: סבג נדל\"ן (Sabag360). Primary use: תיעוד, חוקות סוכנים וניהול ידע — לא פיתוח קוד רץ",
      "Source control: github.com/nsabag4/Nsabag (ריפו פרטי)",
      "Sensitive data locations & audiences: 09-Monday-Agents/agents/03-personal-LOCKED.md ו-10-financial-LOCKED.md — מול נחי בלבד (חוק 7)"
    ],
    "soft_deny": [
      "$defaults",
      "אין לכתוב, לעדכן או למחוק שום פריט במאנדיי מתוך הריפו הזה — קלוד קוד מאמת ריפו בלבד (חוק 13)",
      "אין לשנות קובץ תחת 00-Constitution/ או חוקת סוכן בלי אישור מפורש של נחי (חוק 12)"
    ]
  }
}
```

> ⚠️ **אזהרה קריטית:** מערך שנכתב **בלי** `"$defaults"` **מוחק את כל כללי ברירת המחדל** של אותה מגירה. ב-`soft_deny` זה אומר לאבד את החסימות המובנות של force push, `curl | bash`, פריסה לפרודקשן ועקיפת המצב האוטומטי. תמיד להשאיר את `"$defaults"` במקומו.

**סדר הקדימויות בתוך המסווג:** `hard_deny` חוסם ללא תנאי · `soft_deny` חוסם אחריו · `allow` גובר על `soft_deny` תואם · כוונה מפורשת של המשתמש גוברת על שאר החסימות הרכות. בקשה כללית אינה כוונה מפורשת: "תסדר לי את הריפו" אינו אישור ל-force push; "תעשה force push לענף הזה" — כן.

## אימות

| מה בודקים | איך |
|---|---|
| הכללים נטענו | `/permissions` בסשן חדש משורש הריפו — הכללים מופיעים תחת מקור Project. אזהרת startup = כלל שלא נבדק בפועל |
| המסווג קיבל את ההקשר | `claude auto-mode config` — מדפיס את הכללים האפקטיביים עם `$defaults` פרוס במקומו |
| ביקורת על כללי הפרוזה | `claude auto-mode critique` |
| מה נחסם בדיעבד | `/permissions` ← לשונית **Recently denied**; `r` מסמן ניסיון חוזר |
| איפוס להגדרות ברירת המחדל | `claude auto-mode reset` (נוגע רק ב-`~/.claude/settings.json`) |

**בדיקה חיה, בסשן שנמצא ב-`⏵⏵ auto mode on`:**

1. קריאת `.env` ← **נחסמת**.
2. `git push` ← **עוצר ושואל**.
3. עריכת `00-Constitution/LAWS.md` ← **עוצרת ושואלת**.
4. עריכת קובץ תיעוד רגיל (למשל `06-Development/SERVICES-RELIABILITY-PLAN.md`) ← **רצה בלי שאלה**. זה המבחן שהמצב האוטומטי באמת עובד ולא רק חוסם.
5. קריאה לכלי מאנדיי ← **עוצרת ושואלת**.
